# Routing & APIRouter

## Overview

Routing is the mechanism FastAPI uses to map an incoming HTTP request to the appropriate Python function.

When a client sends a request, FastAPI examines the request path and HTTP method, finds the matching route, executes the corresponding function, and returns a response.

AudioPilot organizes routes using **APIRouter** to keep the backend modular and maintainable.

---

# What is a Route?

A route is an endpoint that responds to a specific HTTP method and URL.

Example:

```python
@router.post("/upload")
async def upload_audio():
    ...
```

This route handles:

```
POST /api/audio/upload
```

Every route consists of:

- HTTP Method
- URL Path
- Handler Function

---

# HTTP Methods

FastAPI supports standard REST methods.

| Method | Purpose |
|---------|----------|
| GET | Read data |
| POST | Create data |
| PUT | Replace existing data |
| PATCH | Update partial data |
| DELETE | Remove data |

Current AudioPilot examples:

```text
POST /api/auth/register

POST /api/auth/login

POST /api/audio/upload

GET /api/audio/my-analysis

DELETE /api/audio/delete-analysis/{id}
```

---

# Why APIRouter?

Without APIRouter:

```text
main.py

2000 lines
```

Everything becomes difficult to maintain.

Instead AudioPilot separates routes by feature.

```text
routes/

auth_routes.py

audio_routes.py
```

Each router manages one part of the application.

---

# Router Registration

Inside main.py

```python
app.include_router(
    auth_router,
    prefix="/api/auth",
    tags=["Authentication"]
)

app.include_router(
    audio_router,
    prefix="/api/audio",
    tags=["Audio Analysis"]
)
```

This automatically prefixes every route.

Example

Inside:

```python
@router.post("/upload")
```

becomes

```
POST /api/audio/upload
```

# Route Anatomy

Example from AudioPilot

```python
@router.post("/upload")
async def upload_audio(

    audio: UploadFile,

    question: str,

    db: Session,

    current_user

):
```

Let's break it down.

---

## Decorator

```python
@router.post("/upload")
```

Registers the endpoint.

Meaning:

```
POST /upload
```

---

## Function

```python
async def upload_audio(...)
```

This function executes whenever the endpoint receives a request.

---

## Parameters

FastAPI automatically understands where data comes from.

Example:

```python
audio: UploadFile = File(...)
```

Means

Receive uploaded file.

---

```python
question: str = Form(...)
```

Means

Receive form data.

---

```python
db: Session = Depends(get_db)
```

Means

Inject database session.

---

```python
current_user = Depends(get_current_user)
```

Means

Inject authenticated user.

# File Upload

AudioPilot uses

```python
UploadFile
```

instead of

```python
bytes
```

Why?

Because UploadFile

- Uses less memory
- Better for large files
- Supports streaming
- Stores temporary files efficiently

Perfect for AI applications.

---

# Form Data

AudioPilot accepts

```python
question: str = Form(...)
```

instead of JSON.

Reason:

The request contains

- Audio file
- Text question

Both are sent as

```
multipart/form-data
```

This is the correct approach.

---

# Dependency Injection

Inside the route

```python
db = Depends(get_db)
```

FastAPI automatically

```
Create Session

↓

Pass Session

↓

Close Session
```

You never manually create the session.

---

# Current User

```python
current_user = Depends(get_current_user)
```

FastAPI automatically

```
Authorization Header

↓

JWT

↓

Decode

↓

Database

↓

Current User

↓

Inject into Route
```

This is why the route doesn't need authentication logic.

# Route Responsibilities

Routes should only

- Receive request
- Validate input
- Call service
- Return response

Routes should NOT

- Perform AI processing
- Write database logic
- Authenticate manually
- Implement business logic

AudioPilot follows this practice well.

---

# Best Practices

- Keep routes thin.
- Use APIRouter.
- Use dependency injection.
- Keep business logic inside services.
- Return consistent responses.
- Validate all inputs.

---

# Common Mistakes

❌ Writing SQL inside routes.

❌ Calling AI models inside routes.

❌ Large route files.

❌ No request validation.

❌ No dependency injection.

# Summary

Routes are the entry point of every request in AudioPilot. They receive incoming HTTP requests, validate inputs, resolve dependencies, delegate business logic to the service layer, and return structured responses. By organizing endpoints with APIRouter and keeping routes lightweight, AudioPilot maintains a modular and scalable backend architecture.
